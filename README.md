# A little sky of our own — Interactive Loy Krathong

เว็บไซต์เกมลอยกระทงแบบ 2D รองรับมือถือและคอมพิวเตอร์ ผู้เล่นเลือกรูปแบบกระทง เลือกหมวดและเขียนคำอธิษฐาน จากนั้นแตะค้างเพื่อปล่อยกระทงลงแม่น้ำ ข้อความจะถูกบันทึกไว้ใน Supabase และอ่านได้เฉพาะบัญชีเจ้าของเว็บไซต์ที่กำหนด UUID ไว้ใน Row Level Security (RLS)

## ไฟล์ในโปรเจกต์

- `index.html`, `style.css`, `app.js` — หน้าเกมและฉากเทศกาล
- `config.js` — URL และ public/anon key ของ Supabase
- `admin.html`, `admin.css`, `admin.js` — หน้าเจ้าของเว็บไซต์สำหรับอ่านคำอธิษฐาน
- `supabase-setup.sql` — ตารางและนโยบายความปลอดภัย RLS

## 1. สร้าง Supabase project

1. เข้า https://supabase.com/dashboard แล้วเลือก **New project**
2. ตั้งชื่อโปรเจกต์ สร้าง Database password ที่คาดเดายากและเก็บไว้ในที่ปลอดภัย
3. เลือก Region ที่เหมาะกับผู้ใช้งาน (Singapore หากมีให้เลือก) แล้วสร้างโปรเจกต์
4. ไปที่ **Authentication → Users → Add user** สร้างบัญชีอีเมล/รหัสผ่านสำหรับเจ้าของเว็บไซต์ และยืนยันอีเมลให้เรียบร้อยตามขั้นตอนของ Dashboard
5. คัดลอก **User UID** ของผู้ดูแลเก็บไว้ ขั้นตอนนี้ต้องทำก่อนรัน SQL

> แนะนำให้ปิดการสมัครสมาชิกสาธารณะใน Authentication settings หลังสร้างบัญชีเจ้าของแล้ว และอย่าแชร์รหัสผ่านผู้ดูแล

## 2. สร้างตารางและล็อกสิทธิ์การอ่าน

1. เปิดไฟล์ `supabase-setup.sql`
2. แทนคำว่า `ADMIN_USER_UUID` ด้วย User UID ของผู้ดูแล (แทนเฉพาะข้อความ UUID ไม่ต้องใส่เครื่องหมายอื่นเพิ่ม)
3. ไปที่ **SQL Editor → New query** วาง SQL ที่แก้แล้ว แล้วกด **Run**
4. ไปที่ **Table Editor** ตรวจว่ามีตาราง `wishes` และเปิด RLS อยู่

นโยบายที่ใช้:

- ผู้เยี่ยมชม (`anon`) ส่งคำอธิษฐานได้ด้วย `INSERT`
- ผู้เยี่ยมชมไม่มีสิทธิ์ `SELECT` จึงอ่านคำอธิษฐานของคนอื่นไม่ได้
- บัญชีที่ล็อกอินจะอ่านได้ก็ต่อเมื่อ `auth.uid()` ตรงกับ UUID เจ้าของที่กำหนดไว้
- ไม่มีนโยบายแก้ไขหรือลบแถวผ่าน API

## 3. เชื่อมเว็บกับ Supabase

1. ใน Supabase เปิด **Project Settings → API** (หรือหน้า API Keys ตามหน้าตา Dashboard รุ่นปัจจุบัน)
2. คัดลอก **Project URL**
3. คัดลอก **publishable key** หรือ legacy **anon public key**
4. เปิด `config.js` แล้วใส่ค่าลงในเครื่องหมายคำพูด:

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://YOUR_PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_PUBLISHABLE_OR_ANON_KEY"
};
```

**ห้ามใช้ `service_role` หรือ secret key ในไฟล์หน้าเว็บเด็ดขาด** เพราะไฟล์เหล่านี้ถูกเผยแพร่สู่สาธารณะได้ ความปลอดภัยของข้อมูลอาศัย RLS เป็นหลัก

## 4. เผยแพร่ด้วย GitHub Pages

1. สร้าง GitHub repository เช่น `a-little-sky-of-our-own`
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ไปไว้ที่ root ของ repository (อย่าอัปโหลดทั้งโฟลเดอร์ซ้อนอีกชั้น)
3. เปิด **Settings → Pages**
4. เลือก **Deploy from a branch**, branch `main`, folder `/ (root)` แล้วกด Save
5. รอ GitHub Pages deploy แล้วเปิด URL ที่ GitHub แสดงให้

## 5. ทดสอบ

1. เปิดหน้าแรกจาก URL GitHub Pages แล้วลองส่งคำอธิษฐานหนึ่งรายการ
2. เปิด `https://YOUR-GITHUB-PAGES-URL/admin.html` แล้วล็อกอินด้วยบัญชีเจ้าของที่สร้างใน Supabase
3. ตรวจว่าข้อความปรากฏในหน้าเจ้าของ
4. เปิดหน้าเว็บในหน้าต่างส่วนตัว/Incognito แล้วตรวจว่าหน้าเกมไม่มีทางเปิดดูรายการคำอธิษฐานได้

## หมายเหตุเรื่องความเป็นส่วนตัวและการใช้งาน

- ข้อความจะถูกส่งไป Supabase เมื่อผู้เล่นปล่อยกระทงสำเร็จเท่านั้น
- อย่าใส่ข้อมูลส่วนตัวที่ไม่ต้องการให้เจ้าของเว็บไซต์เห็นลงในคำอธิษฐาน เพราะเจ้าของเป็นผู้มีสิทธิ์อ่านข้อความ
- RLS จำกัดสิทธิ์การอ่าน แต่โปรเจกต์ตัวอย่างนี้ยังไม่มีระบบป้องกันสแปม/จำกัดจำนวนคำขอต่อ IP จึงควรตรวจสอบการใช้งานจริงและเพิ่ม rate limiting ก่อนเปิดเผยแพร่ในวงกว้าง
- CDN ของ Supabase JS และ Google Fonts ต้องใช้อินเทอร์เน็ตขณะเปิดเว็บ
- ทดสอบการตั้งค่า RLS ด้วยบัญชี/หน้าต่างส่วนตัวก่อนแชร์ลิงก์จริงเสมอ
